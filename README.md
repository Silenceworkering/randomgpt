# 💀 Дедлайныч

> Пока ты отдыхаешь, я слежу за дедлайнами!

Telegram-помощник студентов **АмГУ, группы 6104-ОБ**, для бота **@Dedlainych_AI_bot**.
Русский интерфейс, две подгруппы, личные настройки, PostgreSQL и локальная нейросеть без платного API.

**Репозиторий:** https://github.com/Silenceworkering/randomgpt

**Статус:** исходный код реализован и проверен локально. Живой Telegram-сеанс и размещение
требуют подключения внешних сервисов. Нельзя считать бот запущенным, пока
не добавлен токен и не проведена проверка в учебном чате. Реальных домашних заданий и расписания
в репозитории нет. Пример JSON — только описание формата и автоматически не импортируется.

## Что умеет

- Пошаговая регистрация: подгруппа → время → часовой пояс. По умолчанию предлагается Asia/Yakutsk (UTC+9).
- HTML-меню с inline-кнопками, редактированием экранов, возвратом домой.
- Несколько разрешённых учебных чатов; обработка новых и отредактированных сообщений,
  подписей, пересланного содержимого, фото и документов. История чата до подключения недоступна Bot API.
- Несколько заданий в сообщении, словарь реальных предметов, сроки, подгруппы, ссылки на источник.
- Гибридный разбор: быстрые правила и необязательная нейросеть Groq Free / внешний Ollama, контекст чата с TTL, исправления через подтверждение.
- Неизвестные предметы, уточнения и сомнительные вложения направляются администратору.
- OCR JPG/PNG/WEBP через Tesseract rus+eng, текст PDF, DOCX, TXT. Исходные Telegram file_id сохраняются.
- Ручной импорт реального расписания по датам, учебным неделям, подгруппам,
  преподавателям и аудиториям; отмены и переносы. Изменение расписания не удаляет домашку.
- «Узнать сейчас» ищет ближайший учебный день на горизонте 120 дней. «На завтра» начинает поиск с завтра.
- Личная ежедневная сводка, индивидуальное время и пояс, отключение доставки,
  выделение срочных сроков. Дополнительных навязчивых рассылок нет.
- Индивидуальное выполнение, прогресс, архив по 8 заданий, поиск по тексту, предмету, сроку, выполнению.
- Админское меню: источники, предметы и псевдонимы, проверка, исправление текста/срока/предмета, статистика.
- Миграции, контейнеры, ежедневные резервные копии, CI и необязательное развёртывание после успешного CI.

## Бесплатное подключение Render

**Render Free + Neon Free**, без платного worker и без Render Postgres.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/Silenceworkering/randomgpt)

Сначала создайте бесплатную PostgreSQL в Neon, затем нажмите кнопку и введите `BOT_TOKEN`, `ADMIN_IDS`
и `DATABASE_URL`. [Короткая пошаговая инструкция →](docs/RENDER.md)

Render просыпается по webhook; первое сообщение после сна может обрабатываться с задержкой.
Уведомления вынесены в отдельное бесплатное задание GitHub Actions раз в 30 минут,
которое надо включить через секреты и переменную репозитория. Точность по минутам не гарантируется.
Бесплатные тарифы имеют лимиты; платные ресурсы автоматически не создаются.

## Самый простой запуск через Docker

Потребуется компьютер/сервер с Docker Compose v2. Он должен оставаться включённым для уведомлений.
Установка Docker: https://docs.docker.com/get-started/get-docker/

1. Получите **новый токен** у официального @BotFather: `/mybots` → нужный бот → API Token.
   Если старый токен когда-либо публиковали, отзовите его. Не присылайте токен в учебный чат или GitHub.
2. Скачайте проект и откройте терминал в его папке. Если установлен Git:

   ```sh
   git clone https://github.com/Silenceworkering/randomgpt.git Dedlainych-AI
   cd Dedlainych-AI
   ```
3. Скопируйте `.env.example` в `.env`:

   ```sh
   cp .env.example .env
   ```

4. В `.env` задайте `BOT_TOKEN`, `ADMIN_IDS=[123456789]`, новый сложный `POSTGRES_PASSWORD`.
   Тот же пароль вставьте в DATABASE_URL. Спецсимволы пароля в URL нужно percent-encode;
   проще выбрать длинный случайный пароль из букв и цифр. ID администратора — ваш числовой Telegram ID,
   не username. `ADMIN_IDS` — JSON-массив чисел.
5. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs --tail=100 bot
   ```

Миграции применяются перед запуском. База хранится в named volume `postgres_data`,
не в файловой системе контейнера. PostgreSQL не открывает порт наружу.
**Не выполняйте `docker compose down -v`: это удалит базу.**

Откройте бота → `/start` → зарегистрируйтесь. Администратору тоже нужен `/start`,
иначе бот не сможет первым отправить ему сообщения о проверке.

## Подключение учебного чата

1. Добавьте бота в группу с согласия её участников.
2. В @BotFather отключите Group Privacy: `/setprivacy` → бот → Disable.
   После изменения может потребоваться удалить и добавить бота обратно.
   Альтернатива — необходимые права администратора. Лишние права удаления сообщений не нужны.
3. В личном чате бота администратор выполняет:

   ```text
   /admin chat_add -1001234567890
   /admin chats
   ```

   Замените ID на ID своего учебного чата. Бот проверяет, что его добавили в этот чат.
4. Отправьте новое настоящее задание. Неподключённые чаты и личная переписка не анализируются.
5. Подключите другие чаты той же группы той же командой.

Отключение: `/admin chat_del ID`. Уже сохранённые задания остаются в базе.
Ссылки на сообщения закрытых супергрупп доступны только их участникам.

## Реальные предметы и ИИ

Список реальных дисциплин **не выдумывается**. Импортируйте расписание или внесите их:

```text
/admin subject_add Математика|матеша|матеше
/admin subject_add Информатика|инфа|инфе
/admin subject_add Программирование|прога|проге
/admin subject_add Безопасность жизнедеятельности|бжд
```

Это примеры команд, а не утверждение о программе группы. Сохраните только ваши реальные дисциплины.
«Практика» может означать вид задания, а не название предмета; автоматически дисциплина не назначается.
Повторный `subject_add` с тем же названием обновляет псевдонимы.
`/admin subject_rename ID Новое имя` переименовывает предмет с сохранением связей;
`/admin subject_del ID` удаляет только неиспользуемый предмет.

**Без ИИ:** `AI_PROVIDER=rules`. Это правила и словарь, не нейросеть. Неявные формулировки
могут быть пропущены или отправлены на проверку. Даты без явного срока не создаются.

**Бесплатная локальная LLM:** установите Ollama https://ollama.com/ и загрузите модель:

```sh
ollama pull qwen2.5:7b
```

Понадобится отдельная машина с достаточным объёмом RAM (обычно от 8 ГБ свободной памяти для 7B).
В `.env`: `AI_PROVIDER=ollama`, `AI_BASE_URL=http://АДРЕС_OLLAMA:11434`, `AI_MODEL=qwen2.5:7b`.
Адрес должен быть доступен **из контейнера**; localhost внутри контейнера — сам контейнер.
Используйте приватную сеть, не выставляйте незащищённый Ollama в Интернет.
`AI_API_KEY` используется только необязательным провайдером Groq. В Ollama ключ не передаётся.
Подключение Groq Free, лимиты, контекст, подтверждение исправлений и проверка на настоящих
сообщениях описаны в **[docs/RECOGNITION.md](docs/RECOGNITION.md)**.
По умолчанию внешние запросы выключены. На Render Free не запускайте локальную большую LLM.
Результаты нейросети проверяются по JSON-схеме и цитате исходного сообщения и идут
в очередь администратора. При отказе провайдера — явно обозначенный резерв правил.
Обычные сообщения подключённых групп временно хранятся как контекст: по умолчанию до 12
сообщений на чат, до 2000 символов на сообщение, TTL 120 минут. Имена отправителей не сохраняются.
Просроченный контекст не используется и удаляется при обработке/плановой очистке;
при спящем Render физическое удаление может задержаться до следующего запуска.

## Расписание АмГУ

Проверенные официальные страницы:

- https://amursu.ru/obrazovanie/timetable/
- https://amursu.ru/obrazovanie/timetable/timetable-group/

Страница групп в доступном веб-представлении показывает поиск, но не документированный API
и не строки 6104-ОБ. **Автоматическая синхронизация с АмГУ не заявляется реализованной.**
С другим Telegram-ботом @AmSU_1bot приложение не переписывается.
Рабочий путь — ручной JSON-импорт через личный чат администратора.

Создайте JSON-массив занятий (структура: `docs/schedule.example.json`), замените все примерные
значения на реальные данные и отправьте `.json` документ боту. До 1 МБ и 5000 занятий.

- `date`: ISO-дата, `week`: номер учебной недели (не вычисляется из календарной недели).
- `start`, `end`: время в часовом поясе расписания группы (для АмГУ — Asia/Yakutsk).
- `subject`: точное название; новые названия добавляются в subjects.
- `teacher`, `room`, `note`: необязательные строки.
- `subgroup`: 0 — все, 1 или 2.
- `cancelled`: true для отменённой пары.

Импорт **атомарно заменяет интервал от минимальной до максимальной даты файла** для выбранной группы.
Поэтому в файл включайте полное расписание всех подгрупп на этот интервал, а не отдельную изменённую пару.
При переносе внесите отменённую прежнюю пару и новую пару; обе даты включите в интервал.
Задания сохраняются независимо от занятий. Сроки заданий автоматически не переносятся:
администратор правит их отдельно после проверки.

## Команды студентов и администраторов

Студент: `/start`, `время 20:30`, `пояс Asia/Yakutsk`, `день 2026-10-16`,
`поиск интеграл`, `предмет Математика`, `дата 2026-10-16`, `выполненные`.
Поиск показывает до 8 результатов: уточните запрос; полный архив имеет кнопки страниц.
Все пользовательские задания фильтруются по группе, подгруппе и одобренному статусу.

Администратор: `/admin` показывает команды; 👑 меню показывает статистику и очередь проверки.
Для сомнительного задания назначьте предмет `/admin subject ID Название`,
срок `/admin due ID 2026-10-16` (или `none`), текст `/admin text ID Описание`, затем подтвердите кнопкой.
`/admin inspect ID` показывает исходный текст. `/admin delete ID` убирает ошибочное задание из выдачи,
сохраняя запись для аудита. Редактирование сообщения создаёт предложение на проверку:
прежняя подтверждённая версия остаётся видна студентам **до одобрения**. После одобрения
она становится superseded, её отметки выполнения сохраняются. Новую версию отмечают заново.
Перенос и отмена тоже требуют подтверждения. `/admin target ID ИСХОДНОЕ_ID` связывает
неоднозначное исправление; `/admin as_new ID` явно превращает его в отдельное новое задание.

Административные права выдаёт **только ADMIN_IDS из окружения**. Таблица admins — зеркало для аудита,
её ручное изменение не выдаёт права. Для нового администратора измените окружение и перезапустите бота.

## Уведомления и перезапуски

APScheduler проверяет пользователей каждые 30 секунд. Время каждого пользователя переводится
в его часовой пояс. После перезапуска пропущенная сводка отправляется позднее в тот же день;
за предыдущие дни рассылка не догоняется.

Первичный ключ `(user_id, day, kind)` исключает вторую отправку за день.
Запись **фиксируется до отправки**, чтобы не создавать дубликат при падении после Telegram API.
Компромисс: если процесс упадёт между фиксацией и отправкой, сводка может быть пропущена;
при таймауте API результат доставки неизвестен и повтор автоматически не выполняется.
Гарантировать exactly-once Telegram не позволяет. Ручная кнопка получения домашки доступна всегда.
При блокировке бота пользователем доставка ему отключается.
В polling-режиме PostgreSQL advisory lock разрешает один процесс приложения. В webhook-режиме
используется постоянная очередь с блокировками строк, встроенный планировщик не запускается;
разовую рассылку запускает GitHub Actions. Эти запуски не посылают keepalive-запросы в Render.
Не запускайте одновременно второй экземпляр с другой базой и тем же токеном.

Срочные задания выделяются в сводках; персональная настройка управляет дополнительным предупреждением
в ежедневной сводке. Отдельного потока почасовых уведомлений нет.

## Вложения и ограничения безопасности

Файлы до 10 МБ по умолчанию (MAX_FILE_BYTES, максимум 20 МБ). Другие/большие вложения
сохраняются как Telegram file_id для ручной проверки и не скачиваются для анализа.
PDF: до 30 страниц, без пароля. DOCX: до 30 МБ суммарного распакованного содержимого.
Изображения: ограничение Pillow 20 млн пикселей, OCR с таймаутом.
В контейнере нет root, файловая система read-only, tmpfs ограничен, лимиты CPU/RAM включены.
Это ограничения парсеров, **не антивирусная проверка**. Не открывайте неизвестные вложения без проверки.
Сканы PDF не проходят OCR: пустой текст направляется на проверку с сохранением исходника.

Telegram file_id не является независимой резервной копией файла. Для долгосрочного независимого
архива материалов потребуется отдельное объектное хранилище; оно в эту поставку не подключено.
Альбомы Telegram приходят отдельными сообщениями: каждая фотография сохраняется и анализируется
отдельно, объединение их в один документ не реализовано.

HTML из пользовательских текстов экранируется. Секреты хранятся только в окружении.
Исходные сообщения учебных чатов находятся в БД, доступ к ней ограничьте администраторами.
Тексты личных сообщений настроек не сохраняются и не публикуются.

## Резервные копии и восстановление

Сервис backup делает pg_dump сразу после старта и каждые 24 часа. Хранит 14 дней в `./backups`.
Переносите копии на другой носитель/сервер: копия на том же диске не защищает от его потери.

Восстановление (заменяет данные выбранной БД, сначала остановите бота и сделайте текущую копию):

```sh
docker compose stop bot
cat backups/ИМЯ.dump | docker compose exec -T db sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" pg_restore -U dedlainych -d dedlainych --clean --if-exists'
docker compose up -d bot
```

Не восстанавливайте непроверенные дампы в рабочую базу. Сначала проверяйте восстановление в отдельной БД.

## Бесплатное размещение: что реально возможно

Исследованы официальные ограничения 14 октября 2026:

- Render Free: сервис засыпает через 15 минут без входящих запросов; бесплатные background workers
  отсутствуют, PostgreSQL истекает через 30 дней. Для постоянного polling не подходит; в этой поставке есть спящий webhook-режим с Neon Free и отдельной рассылкой.
  https://render.com/docs/free
- Koyeb Free: автоматическое засыпание после часа без трафика. Для постоянного планировщика не подходит.
  https://www.koyeb.com/docs/run-and-scale/scale-to-zero

- Oracle Always Free: существуют постоянные бесплатные ресурсы, но неактивные VM могут изыматься;
  при обычной регистрации запрашивают карту. Возможность регистрации зависит от аккаунта/региона.
  https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm
  https://www.oracle.com/cloud/free/faq/
- Google Cloud: есть лимит e2-micro и диска, но требуется billing account, действуют региональные
  ограничения и квоты. Ресурсы сверх бесплатных лимитов могут оплачиваться, поэтому автоматически не создаются.
  https://docs.cloud.google.com/free/docs/free-cloud-features

Для бесплатного Render см. [docs/RENDER.md](docs/RENDER.md): webhook и Neon, без обещания постоянного процесса.

Гарантированный бесплатный облачный сервер 24/7 без карты и с постоянной PostgreSQL
**не найден и не обещается**. Не применяются фиктивные ping-запросы для обхода сна.
Практичный вариант без оплаты облака — ваш постоянно включённый Linux-компьютер/сервер
(возможны расходы на электричество и Интернет). Docker Compose выше готов для такого размещения;
входящие порты боту не нужны. Если своего сервера нет — потребуется выбрать доступный вам VPS
или университетский сервер. Платные ресурсы автоматически не создаются.

Перед обновлением сделайте резервную копию. `scripts/deploy.sh` автоматизирует backup,
сборку, остановку, миграцию и перезапуск. Скрипт запускается из существующего клона на сервере,
не из непроверенного PR. Используйте только совместимые миграции без удаления данных.
При ошибке миграции бот остаётся остановлен; проверьте журнал и исправьте миграцию, не удаляйте БД.

GitHub Actions на каждый push/PR: Python 3.12, установка закреплённых версий, синтаксис,
Ruff, поиск известных форматов секретов, миграции, pytest на PostgreSQL, сборка wheel и Docker.
Проверка секретов эвристическая, не гарантирует обнаружение любого возможного ключа.
Проверки расходуют бесплатные лимиты GitHub Actions, никаких дополнительных платных API нет.

Автообновление отключено по умолчанию. Для него после подключения репозитория:

1. Установите GitHub self-hosted runner на выделенном доверенном сервере с меткой `dedlainych`.
2. Разместите клон проекта в `/opt/Dedlainych-AI`, настройте `.env`, доступ git и Docker.
3. Создайте GitHub environment `production`; доступ ограничьте владельцем и веткой main.
4. Задайте repository variable `AUTO_DEPLOY=true`.

Deploy выполняется только после успешного job test для push в main. Не используйте этот runner
для посторонних репозиториев или недоверенного кода. Для Render self-hosted runner не нужен: `render.yaml` использует обновление после успешных проверок.
Подробности — [docs/RENDER.md](docs/RENDER.md). Внешний Render-аккаунт к текущей сессии не подключён.

## Если что-то не работает

- **Бот молчит:** проверьте BOT_TOKEN, доступ api.telegram.org, исходящие HTTPS, `docker compose logs bot`.
- **Conflict / другой getUpdates:** выключите вторую копию бота, не запускайте несколько polling-инстансов.
- **Чат не читается:** `/admin chats`, членство бота, Privacy Mode и новые сообщения после подключения.
- **Домашка на проверке:** реальный список предметов, псевдонимы, 👑 очередь, `/admin inspect ID`.
- **Расписания нет:** импортируйте JSON с полным интервалом и нужной подгруппой. Не загружайте пример как реальные пары.
- **OCR не работает:** проверьте `tesseract --list-langs`, должны быть rus и eng. Исходный файл сохранён.
- **База недоступна:** одинаковый пароль в URL и POSTGRES_PASSWORD, `db` в Compose, `localhost` только вне контейнера.
- **Не пришла сводка:** время/пояс, enabled, зарегистрированность, доступность процесса и notification_history.
- **Ollama недоступна:** адрес из контейнера, модель загружена, RAM; бот продолжит разбор правилами.
- **GitHub:** проект размещается в существующем `Silenceworkering/randomgpt`. Предыдущий проект
  сохранён в ветке `backup/before-dedlainych-2026-10-14`. Не вставляйте GitHub-токены в код или чат.

## Что ещё требует настройки или разработки

Токен бота, ADMIN_IDS, учебные чаты, реальный список дисциплин и расписание, сервер и резервные копии
на другом носителе настраиваются владельцем. Нейросеть требует необязательного Groq Free либо своего Ollama. Автоматический адаптер API АмГУ,
семантическое объединение дублей, автоматическое связывание уточнений с отдельным старым сообщением,
OCR сканов PDF и объединение альбомов не реализованы. Исправления исходного сообщения обрабатываются,
отдельные сообщения-уточнения направляются на ручную проверку. Повторы отсекаются по нормализованному
точному содержимому, предмету, сроку и подгруппе; перефразированные дубли требуют проверки.
Архитектура хранит group_code у сущностей и изолирует группы; выбор других университетов/групп
в публичной регистрации пока не добавлен. Для этого потребуется справочник университетов и приглашения.

### Подбор ДЗ по двум чередующимся неделям 6104-ОБ

В код внесён список предметов обеих недель, переданный владельцем группы. Он используется
для домашки, отдельная кнопка расписания убрана. Python исправлен из опечатки «Pyhon»;
«Основы программирования», «Основы программирования на Python», «Начертательная геометрия»
и «Начертательная геометрия и инженерная графика» сохранены отдельными дисциплинами.
Общего псевдонима «матеша» нет: он неоднозначен между тремя математическими предметами.

Администратор один раз сообщает номер недели и дату её понедельника, например:
`/admin week 1 2026-10-12`. Это пример привязки, а не установленный факт о текущей неделе.
Команда сохраняет предметы, псевдонимы и повторяющийся двухнедельный шаблон в PostgreSQL.
Ничего не включается без команды администратора. Перезапуск и смена календарного года
не сбивают чередование. Подгруппы учитываются; суббота и воскресенье пустые по переданным данным.
Шаблон действует с указанного понедельника до `/admin week_off`. В конце семестра отключите его;
каникулы, праздники и изменения университета автоматически не обнаруживаются.
Повтор команды меняет привязку, сохраняя домашку. Импорт конкретной даты имеет приоритет
над шаблоном **на весь день**, поэтому при переносах импортируйте полный изменённый день.

Для ДЗ всё равно подключите учебный чат через `/admin chat_add ID`. Бот не получает историю чата:
после подключения обрабатываются новые сообщения. Сомнительные задания — в очереди администратора.
Ежедневная отправка на Render Free требует настройки GitHub Actions, описанной в `docs/RENDER.md`.
