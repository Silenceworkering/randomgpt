# Умное распознавание ДЗ

Изменения предлагаются в отдельном PR. Они не включают слияние, деплой, смену тарифа
или подключение ключей к действующему сервису.

## Что уже было и что изменилось

Существовали разрешённые источники, OCR/документы, правила, адаптер Ollama, подтверждение
сомнительных заданий, персональные отметки выполнения, PostgreSQL, недельный план 6104-ОБ,
уведомления и надёжная очередь webhook. Сохраняются их интерфейсы и данные.

Теперь обычные сообщения разрешённого чата могут служить коротким контекстом. Быстрые
правила распознают явные инструкции и краткие записи вроде «По матану 15–20». При подключении провайдера
содержательные сообщения дополнительно проверяет нейросеть, даже без ключевого слова «ДЗ».
Она проверяет и внешне явную инструкцию: та может оказаться частью шутки.
Она классифицирует вопрос, шутку, предположение, разговор и сообщение о задании.
Неоднозначные кандидаты идут в админскую очередь; безопаснее лишняя проверка, чем ложное подтверждение.
Режим `rules` не является нейросетью и не гарантирует понимания произвольной речи.

Нейросеть возвращает JSON, проверяемый Pydantic. Предмет допускается только из справочника.
Для каждого задания требуется точная цитата текущего сообщения; из старого контекста задания
повторно не извлекаются. Срок рассчитывается только из явного выражения в цитате,
а не из предложенной моделью даты. Отсутствие срока сохраняется как `NULL`.
Неоднозначный предмет тоже `NULL`. Даже высокая уверенность модели сама по себе не даёт
статус подтверждённого задания: смысловые результаты проходят администратора.
Это консервативная политика, а не обещание безошибочной классификации.

## Бесплатный ИИ на Render

Проверено по официальным источникам 15 октября 2026:

- [Render Compute Plans](https://render.com/docs/compute-plans): Free — 512 МБ RAM.
  Большая модель Ollama на таком экземпляре не подходит. Адаптер Ollama сохранён для отдельной машины.
- [Groq Free: лимиты](https://console.groq.com/docs/rate-limits): в бесплатной таблице есть
  `openai/gpt-oss-20b`. Реальные квоты конкретного аккаунта могут отличаться; проверяйте консоль Groq.
- [Структурированные ответы Groq](https://console.groq.com/docs/structured-outputs): модель
  поддерживает JSON. Приложение использует JSON object mode и дополнительно валидирует схему локально.

На Render выполняется только небольшой HTTP-запрос, без загрузки весов модели.
`openai/gpt-oss-20b` здесь — модель на Groq, отдельный ключ или платный API OpenAI не нужен.
Доступность регистрации и модели в вашем регионе нужно проверить самостоятельно.
Работа с действующим ключом в этом PR не проверялась: ключ не предоставлен.
Автоматические тесты проверяют клиент и защитные условия с тестовыми ответами, а не качество модели вживую.

### Включение после принятия PR

1. Создайте ключ в своём **бесплатном** аккаунте Groq. Не подключайте платный тариф или автопополнение.
2. В Render → Environment укажите:

   ```dotenv
   AI_PROVIDER=groq
   AI_EXTERNAL_ENABLED=true
   AI_API_KEY=ваш_ключ_только_в_Render
   AI_GROQ_MODEL=openai/gpt-oss-20b
   AI_DAILY_REQUEST_LIMIT=100
   AI_MAX_OUTPUT_TOKENS=1536
   AI_TIMEOUT_SECONDS=20
   CONTEXT_TTL_MINUTES=120
   CONTEXT_MESSAGE_LIMIT=12
   ```

   Не присылайте ключ в переписку, не сохраняйте его в репозиторий.
3. Если отдельное задание уведомлений GitHub Actions обрабатывает очередь при спящем Render,
   настройте в репозитории Actions **secret** `AI_API_KEY`, **variables** `AI_PROVIDER=groq`,
   `AI_EXTERNAL_ENABLED=true`, `AI_GROQ_MODEL=openai/gpt-oss-20b`, `AI_DAILY_REQUEST_LIMIT=100`.
   Используйте одинаковые лимиты на обоих исполнителях. Иначе восстановление очереди Actions работает
   в режиме правил, даже если на Render включена нейросеть. Уведомления сами по себе ИИ не вызывают.

Без этих действий ничего не отправляется во внешний API. Одного ключа недостаточно:
нужны одновременно выбранный `groq` и `AI_EXTERNAL_ENABLED=true`.
`AI_PROVIDER=rules` или `AI_EXTERNAL_ENABLED=false` выключают внешнюю обработку.
Облачный endpoint фиксирован: `https://api.groq.com/openai/v1/chat/completions`, ключ не
передаётся произвольному `AI_BASE_URL` (эта настройка относится только к Ollama).

Суточная квота глобальна для общей базы, хранится в `ai_daily_usage`, сбрасывается по UTC.
Место резервируется отдельной транзакцией **до HTTP**, поэтому перезапуск, ошибка или откат
транзакции ДЗ не возвращают потраченный запрос. Конкурентные экземпляры делят одну квоту.
Даже неуспешный вызов расходует одно место. Лимит 0 запрещает все внешние вызовы.
Вход ограничен 18 000 символов вместе со схемой/инструкциями; выход ограничен токенами,
есть таймаут и нет автоматических повторов HTTP. При 429, ошибке, отказе, некорректном JSON
или исчерпанной квоте работают правила. Лимиты числа запросов не являются денежным бюджетом:
если владелец сам переключит аккаунт провайдера на платный, приложение не может проверить его биллинг.
Платные вызовы проект не включает и такой тариф не требует.

## Контекст и данные

Только сообщения чатов из `connected_chats`; никакой истории Telegram или чужих чатов.
Контекст хранится в PostgreSQL отдельно для каждого chat_id: максимум 12 записей по 2000 символов,
TTL 120 минут по времени исходного/отредактированного сообщения. Настройки ограничены сверху.
Устаревшие данные не используются даже после долгого сна Render. Записи удаляются при следующей
обработке/запуске уведомлений; во время сна физическая очистка не исполняется.
Тексты принятых заданий, их источники и материалы сохраняются отдельно как раньше.
В контексте нет Telegram user_id, имён или профилей отправителей; личные чаты не анализируются.
При включении Groq текст текущего сообщения и ограниченный контекст разрешённого чата
передаются внешнему провайдеру. Участники учебного чата должны об этом знать.

Ответ на сообщение даёт подсказку об исходном задании. Давняя цитата вне TTL не используется
для автоматического определения предмета. Пересланные материалы поступают на проверку актуальности:
«завтра» в пересланном тексте могло относиться к другому дню.
Ссылки `t.me/username/id` и `t.me/c/.../id` сохраняются, когда позволяют тип и адрес чата.

Шаблон двух недель 6104-ОБ и подгруппы сохраняются, используются для сводки и как
неподтверждённая подсказка списка предметов на завтра. Ближайшая пара **не становится сроком сдачи**.
Если шаблон уже настроен, повторять настройку не нужно. Для добавленных псевдонимов иностранного языка
можно повторить `/admin week 1 2026-10-12` (это подтверждённая владельцем привязка на 12–18 октября 2026).
Не объединены неодинаковые дисциплины, например линейная алгебра и матанализ.

## Исправления, переносы и отмены

1. Исходное задание остаётся `approved`.
2. Новая реплика или редакция сообщения создаёт запись `pending` с операцией `update` или `cancel`.
   Это предложение, а не ещё одно подтверждённое ДЗ. В очереди видны прежнее и предлагаемое содержание,
   сроки, подгруппы и причина проверки.
3. Если исходное задание найдено однозначно среди свежих сообщений того же чата, записывается его ID.
   Ответ имеет приоритет. Несколько возможных заданий остаются без выбранной цели.
4. Администратор открывает 👑 Админская → 🧐 Проверить задания. При необходимости:

   ```text
   /admin inspect 12
   /admin target 12 5
   /admin text 12 Полная исправленная формулировка
   /admin due 12 2026-10-19
   /admin subject 12 Математический анализ
   ```

   Сначала назначьте цель, затем уточняйте поля. Команда `target` не применяет изменение.
   Если это отдельное новое ДЗ, используйте `/admin as_new 12`, затем назначьте предмет и подтвердите.
5. Только кнопка ✅ заменяет исходную версию; при отмене убирает её из студенческой выдачи.
   Кнопка 🗑 отклоняет предложение, не трогая оригинал.

Для замены номера «вместо 24 делаем 26» сохраняется прежняя формулировка с заменой номера,
если в оригинале этот номер найден. Сложные исправления проверяйте полностью и правьте `text`.
Перенос срока и ограничение подгруппы сохраняют неизменённые поля. Исходные материалы копируются
по Telegram file_id, исходные файлы не удаляются. Старые индивидуальные отметки выполнения
остаются на старой версии; новая версия требует новой отметки.

Подтверждение выполняется с блокировками строк и проверкой снимка оригинала. Если задание
уже изменилось или отменено, устаревшее предложение не применяется: проверьте и заново назначьте цель.
Повторное получение update/сообщения не создаёт второе задание и не вызывает ИИ заново.
Устаревшая редакция не отменяет более новую. Существующие записи PostgreSQL сохранены;
миграция добавляет таблицы/поля без удаления данных.

## Личный чат и диагностика

Сохраняются просмотр, поиск, архив, материалы, индивидуальное выполнение и сводки.
Добавлена кнопка 🚨 Срочные: невыполненные задания со сроком до завтра включительно,
в том числе просроченные. В карточке задания есть 🧠 Запрос для ChatGPT: отдельный блок
текста для копирования. Для короткого запроса доступна кнопка копирования; Telegram ограничивает
её 256 символами. Для длинного нажмите на блок кода; кнопка «Полный запрос (.txt)» сохраняет всё условие без сокращения.
При необходимости добавьте материалы.
Бот не решает задания внешним API автоматически.

Диагностика содержит только фактический провайдер, техническую причину резервного режима,
число созданных/ожидающих записей и типы ошибок. Ни исходные сообщения, ни имена,
ни токены, ни ключи в журнал приложения не выводятся. `ai_processing_logs` хранит ссылки
на источники, имя провайдера и количество результатов. Ошибка группового обработчика
возвращает сообщение в устойчивую очередь повторной обработки вместо потери update.

## Проверка после одобрения и деплоя

Сначала используйте отдельный тестовый чат, добавленный через `/admin chat_add ID`.
Не отправляйте вымышленные задания в настоящий учебный источник.

1. «По матану решить №24» — задание по математическому анализу после настройки предметов.
2. Ответом: «Короче, вместо 24 делаем 26» — предложение, оригинал остаётся виден.
   Проверьте очередь и подтвердите: появляется версия №26.
3. Ответом: «Это только для первой подгруппы» — предложение изменить подгруппу.
4. «Препод перенёс сдачу на понедельник» — перенос только после выбора исходного задания и одобрения.
5. «Нам к пятнице 24 номер и вопросы на 14 странице» — без контекста предмет неизвестен;
   после обсуждения матана предмет лишь предположен, результат на проверке.
6. «Что задали по матану?», «Возможно, таблицу надо сделать», шутка — не должны стать
   подтверждённым ДЗ. В rules неоднозначная фраза может попасть на проверку.
7. Измените исходное сообщение, перезапустите сервис, проверьте отсутствие дубликатов и сохранность оригинала.
8. Откройте сводку под обеими подгруппами, срочные задания, материалы, отметки и запрос для ChatGPT.
9. С Groq проверьте также фразу без ключевых слов, например «Второй текст своими словами, сказала она»
   после обсуждения иностранного языка. Оцените результат в очереди; смысловое качество зависит от модели.
10. Отключите внешний ИИ или установите квоту 0: меню/уведомления работают, анализ переходит на правила.

Сначала дождитесь успешных проверок PR. Только после подтверждения владельцем слейте PR,
затем дождитесь проверок main и нового деплоя.
Render остаётся Free web service с webhook, `/health` и штатным `scripts/start.sh`:
Alembic применит `49bc10000001`. В feature-ветке нет отдельного платного сервиса или автоматического деплоя.
Перед миграцией действующей базы рекомендуется штатная резервная копия.
