# Самый простой запуск Дедлайныча на Render

**Это платный вариант.** Подготовка файлов в GitHub ничего не списывает. Расходы начнутся,
только когда вы подтвердите создание ресурсов в своём Render-аккаунте.

[Открыть настройку Render](https://render.com/deploy?repo=https://github.com/Silenceworkering/randomgpt)

## Что потребуется ввести

Только два значения:

| Поле | Что указать |
|---|---|
| `BOT_TOKEN` | Новый токен @Dedlainych_AI_bot из @BotFather |
| `ADMIN_IDS` | Ваш числовой Telegram ID в квадратных скобках, например `[123456789]` |

Не отправляйте токен в чат и не добавляйте его в GitHub. ID не является токеном.
Если администратора несколько: `[123456789,987654321]`. Пустой список `[]` оставит бота без администраторов.

## Пять шагов

1. Откройте ссылку выше и войдите в Render через GitHub.
2. Если Render запрашивает доступ к репозиторию, разрешите `Silenceworkering/randomgpt`.
3. В форме Blueprint введите `BOT_TOKEN` и `ADMIN_IDS`.
4. Проверьте список и стоимость ресурсов. Должны быть **один Background Worker** `dedlainych-bot`
   и **одна PostgreSQL** `dedlainych-db`. Если платный вариант не подходит — остановитесь до подтверждения.
5. Подтвердите создание кнопкой **Deploy / Apply** (название зависит от интерфейса).
   Дождитесь успешного запуска worker, затем откройте @Dedlainych_AI_bot и отправьте `/start`.

Render сам соберёт Docker-образ, создаст пароль PostgreSQL и передаст строку подключения боту.
Копировать адрес базы, создавать Docker Compose или указывать порт не нужно.
Если форма не открылась, в Render выберите **New → Blueprint**, укажите этот репозиторий,
ветку **main** и путь **render.yaml**. Не выбирайте Web Service: этот бот получает сообщения polling-способом.

На минимальном тарифе большие OCR-задания могут упираться в память: исходный Telegram file_id
при этом сохраняется для проверки. Следите за памятью worker; увеличение тарифа оплачивается отдельно.

## Сколько стоит

Проверены официальные условия 14 октября 2026. В `render.yaml` явно указаны минимальные платные
compute-планы: worker `0.5c-512mb` и PostgreSQL `0.1c-256mb`, диск базы 1 ГБ.
Ориентир — **$7/месяц за worker + $6/месяц за вычисления PostgreSQL**, плюс хранилище,
возможные дополнительные расходы по лимитам и налоги. Итоговую сумму смотрите в форме Render.
Это не гарантия фиксированного счёта: тарифы и условия вашего аккаунта могут отличаться.

Бесплатный worker для этого способа запуска не предусмотрен. Free Web Service засыпает,
а Free PostgreSQL истекает через 30 дней. Поэтому они не выбраны в готовой конфигурации.

Источники: [стоимость](https://render.com/pricing),
[планы](https://render.com/docs/compute-plans), [ограничения Free](https://render.com/docs/free).

## После запуска

- Пройдите регистрацию в личном чате бота. Администратору тоже нужно нажать `/start`.
- Добавьте бота в учебный чат, отключите Group Privacy через BotFather или выдайте подходящие права.
- Подключите чат командой `/admin chat_add -100ВАШ_ID`.
- Добавьте реальные предметы и загрузите реальное расписание JSON-файлом — подробнее в README.
- По умолчанию используется бесплатный разбор правилами (`AI_PROVIDER=rules`), без обращения к платным API.
  Нейросеть Ollama в Render автоматически не создаётся и дополнительно не оплачивается.

До добавления реальных материалов домашка и расписание будут пустыми — это нормально.

## Обновление кода

Worker настроен на обновление из `main` **после успешных GitHub Actions** (`checksPass`).
Для работы этой функции связывайте репозиторий с вашим GitHub-аккаунтом в Render.
Если Render не видит результаты проверок, проверьте доступ Render GitHub App к репозиторию
и Auto-Deploy в настройках сервиса; вручную запускайте только коммит с зелёными проверками.

Перед запуском новой версии Render применяет Alembic-миграции через pre-deploy command.
Новая копия до 180 секунд ждёт освобождения PostgreSQL-блокировки старой версией и не читает Telegram
одновременно с ней. Держите **Instances = 1** и не запускайте второй сервис с тем же токеном.
При ожидании обновления в логах появится «Ожидание завершения предыдущего экземпляра».

Публичная кнопка предназначена для владельца этого репозитория. Если копируете конфигурацию себе,
сначала смените источник на собственный fork, чтобы чужие изменения не обновляли вашего бота.

## База данных и резервные копии

База — отдельный управляемый PostgreSQL Render, данные сохраняются после перезапуска worker.
Внешний доступ к БД отключён (`ipAllowList: []`), worker подключается по внутренней сети того же региона.
Пароль автоматически создаёт Render. Приложение принимает стандартный `postgresql://` URL.

Compose-сервис backup на Render не запускается. Используются резервные копии платного Render Postgres:
PITR в Hobby охватывает последние 3 дня, в Pro и выше — 7 дней. Для длительного хранения скачивайте
экспорты через панель Render. Не удаляйте базу для исправления ошибки деплоя.
[Официальная инструкция по восстановлению](https://render.com/docs/postgresql-backups).

## Если запуск не удался

Откройте `dedlainych-bot → Logs`:

- **Нужен порт / No open ports:** создан Web Service вместо Background Worker. Используйте Blueprint.
- **BOT_TOKEN:** проверьте токен в Environment. Сам токен в скриншотах и сообщениях не публикуйте.
- **ADMIN_IDS:** нужен JSON-массив чисел, без `@username` и без кавычек вокруг всего массива.
- **Другой экземпляр уже работает:** выключите локального бота/второй Render-сервис;
  для обычного обновления дождитесь завершения старой версии.
- **Ошибка базы или миграции:** проверьте состояние `dedlainych-db` и pre-deploy logs.
  Не подставляйте pooled/PgBouncer URL: блокировке требуется прямое подключение.
- **Out of memory:** слишком тяжёлое вложение для 512 МБ. Проверьте размер файла и лимиты;
  самостоятельно не повышайте тариф, если не согласны с новой стоимостью.

Кнопка готовит развёртывание, но не означает, что бот уже запущен. Без вашего Render-аккаунта,
введения секретов и подтверждения расходов создание ресурсов не выполняется.
