## Что покрывают автоматические тесты

- Регистрация и повторный вход; хранение персональных настроек и подгруппы.
- Валидация подгруппы, времени и формата расписания.
- Исключение обычной переписки, несколько предметов, относительные/явные сроки, отсутствие срока.
- Сомнительные предметы и исправления, извлечение номера подгруппы.
- Резервный разбор при отказе LLM; проверка JSON и отбрасывание выдуманного предмета/даты.
- Разрешённые/неразрешённые источники, дубликаты, редактирование и прежние версии.
- Сохранение file_id при нераспознанном вложении, pending-статус.
- PDF, DOCX, TXT, ограничения размера и формата; отдельный unit-тест вызова OCR.
- Импорт расписания и повторный импорт, подгруппы, ближайший день, сохранность заданий.
- Сводка и настоящий вызов обработчика «Узнать сейчас» с БД и подменённым Telegram-транспортом.
- Отсутствие расписания без вымышленных занятий.
- Личное выполнение, защита данных другой группы, фильтрация подгруппы.
- Персональное время/пояс, отключение доставки, перезапуск объекта отправителя без дубля.
- Запрет административного callback обычному пользователю.
- Защита от второго экземпляра PostgreSQL advisory lock.
- Набор кнопок и сохранение валидного HTML при длинном тексте.

Тестовая fixture удаляет таблицы **только в выделенной тестовой БД**; для внешней PostgreSQL
имя базы должно содержать test. Не подставляйте рабочую DATABASE_URL в TEST_DATABASE_URL.

## Что не проверено живым внешним сервисом

- Telegram getUpdates/sendMessage/download/getChat: реальный BOT_TOKEN не предоставлен.
- Нейросетевая модель Ollama: клиент проверен с подменой HTTP, настоящая модель не запускалась.
- Автоматическая синхронизация расписания АмГУ: адаптера нет, ручной импорт проверен.
- GitHub Actions на сервере GitHub: workflow создан, но репозиторий не удалось создать.
- Авторазвёртывание и доставка настоящему студенту: сервер/токен/сервисы не подключены.
- Антивирусная проверка вложений: не реализована; есть ограничения размера/формата/ресурсов.

## Бесплатный Render Free + Neon Free

Платный worker и платная Render PostgreSQL убраны из render.yaml. Новый Blueprint содержит только
Free Web Service. Добавлены HTTPS webhook с секретным заголовком, постоянная очередь TelegramInbox,
повторная обработка и удаление сырого JSON после успеха, разовая рассылка из GitHub Actions.
Проверены 403 для неправильного секрета, 400 для неверного update, 503 при невозможности сохранить
событие (для повторной доставки Telegram), повторы update_id, сохранность очереди при перезапуске,
блокировка одной записи между процессами, идемпотентные кнопки выполнения и параллельный сбор заданий.
Проверка YAML подтвердила plan: free и отсутствие databases/worker. Полный авторизованный Blueprint API
и живой Neon/Render ещё не проверены: аккаунты и реальные секреты не подключены. Платные ресурсы не создавались.
GitHub Actions для сводок выключен до установки NOTIFICATIONS_ENABLED=true и нужных secrets.

Дополнительно проверено, что истёкший callback после холодного старта не мешает открыть меню.

Проверены сроки относительно даты исходного сообщения при отложенной обработке после сна.

15 октября исправлена совместимость с base64-секретами Render generateValue: проверены регистрационный
формат, приём заголовка и отказ для исходного неподходящего значения, сохранение действующих секретов
и отсутствие секретного ввода в тексте ValidationError. SQLite-тесты используют временный файл
с независимыми соединениями вместо одной общей in-memory транзакции для HTTP и фоновой очереди.
